# Observability & Analytics

Observability is a first-class citizen inside Kryneth Gateway, designed to run asynchronously to ensure zero latency overhead on the request execution path.

---

## 1. High-Performance Telemetry Pipeline

Kryneth uses a split-concurrency model to ingest and buffer metrics:
1.  **Ingestion (Hot Path)**: As client requests resolve, the proxy spawns a non-blocking task that writes transactional metadata to an in-memory Tokio MPSC channel.
2.  **Buffering (Async Worker)**: A background worker thread drains the channel, batches traces, and performs highly optimized bulk-inserts into **ClickHouse** (`kryneth_tracer`).
3.  **Visualization**: The React Dashboard queries the ClickHouse data to render real-time telemetry graphs, latency charts, and cache performance metrics.

---

## 2. Dashboard Metrics

The Enterprise admin dashboard monitors:
-   **Upstream Provider Latency**: Visualizes P50, P90, and P99 response velocities across Groq, OpenAI, and Anthropic.
-   **Cache Hit / Miss Ratios**: Visualizes token and cash savings generated by semantic caching.
-   **Firewall Block Count**: Real-time counter of runaway loop interceptions and compliance blocks.

---

## 3. Configuration Reference

Configure these environment variables in your deployment setup:

| Env Variable | Requirement | Default | Description |
| :--- | :--- | :--- | :--- |
| `CLICKHOUSE_URL` | **Required** | *Empty* | HTTP endpoint of the ClickHouse analytics server used for telemetry records. |
| `RUST_LOG` | **Optional** | `info` | Control logging verbosity for tracing (e.g. `trace`, `debug`, `info`). |
