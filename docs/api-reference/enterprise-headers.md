# Enterprise HTTP Headers Specification

Kryneth Gateway leverages custom HTTP request and response headers to manage advanced features such as L7 routing control, tenant isolation, semantic caching verification, telemetry propagation, and circuit-breaker diagnostics.

---

## 1. Enterprise Request Headers

These headers allow client applications and internal microservices to control and direct requests through the gateway pipeline.

### `x-kryneth-model`
-   **Type**: `String`
-   **Requirement**: **Required**
-   **Description**: The virtual target model identifier mapped by the client application (e.g. `gpt-4o`, `llama-3`). The gateway uses this header to resolve upstream bindings and select the corresponding rate-limiting bucket.
-   **Example**: `x-kryneth-model: gpt-4o`

### `x-tenant-id`
-   **Type**: `String (UUIDv4)`
-   **Requirement**: **Required** (automatically resolved from credentials if absent)
-   **Description**: The tenant workspace identifier that scopes the API context, rates, and storage. Used to isolate resources across multiple tenants.
-   **Example**: `x-tenant-id: 00000000-0000-0000-0000-000000000001`

### `x-kryneth-routing-strategy`
-   **Type**: `String (Enum)`
-   **Requirement**: **Optional** (defaults to `static-fallback`)
-   **Description**: Controls dynamic target selection. Overrides default routing algorithms with explicit developer intentions:
    -   `latency-priority`: Routes traffic to the lowest-latency active provider.
    -   `cost-optimized`: Prefers target providers with the lowest token expense profiles.
    -   `static-fallback`: Strictly respects static priorities defined in model configurations.
-   **Example**: `x-kryneth-routing-strategy: latency-priority`

### `x-kryneth-chaos`
-   **Type**: `Integer (Boolean: 0 | 1)`
-   **Requirement**: **Optional** (default: `0`)
-   **Description**: Flags compliance and proxy layers to inject artificial delays, synthetic failures, or payload drops. Used to validate downstream system resilience and circuit-breaker recovery.
-   **Example**: `x-kryneth-chaos: 1`

## 2. Enterprise Response Headers

These headers are injected by the Kryneth Gateway to provide clients and tracing frameworks with structural insights into request execution details.

### `X-Kryneth-Loop-Count`
-   **Type**: `Integer`
-   **Description**: Injected by agentic tracking middleware. It counts the recursive transaction depth of agent cycles. If this count exceeds safe execution boundaries (to prevent infinite loops), the gateway terminates the request with a `429 Loop Detected` response.
-   **Example**: `X-Kryneth-Loop-Count: 3`

### `X-Kryneth-Cache-Status`
-   **Type**: `String (Enum)`
-   **Description**: Displays the resolution status of the semantic cache checks:
    -   `HIT`: The prompt matched a cached entry in L1 memory or L2 vector databases. The request bypassed downstream LLM execution.
    -   `MISS`: The prompt required real-time upstream dispatch. The response is subsequently cached.
    -   `BYPASS`: Cache lookup was skipped due to client configuration or transactional requirements.
-   **Example**: `X-Kryneth-Cache-Status: HIT`

### `x-kryneth-trace-id`
-   **Type**: `String (UUIDv4)`
-   **Description**: A unique execution identifier generated by the edge gateway middleware. It correlates logs and metric points inside the ClickHouse telemetry database (`kryneth_tracer`).
-   **Example**: `x-kryneth-trace-id: 3c5e8bdf-4a69-4e78-98e3-9824bc89f6d7`

### `x-kryneth-session-id`
-   **Type**: `String`
-   **Description**: Associates multiple sequential completions or prompt turns into a single logical session, facilitating audit and conversational trail grouping.
-   **Example**: `x-kryneth-session-id: session-acme-12345`

### `x-kryneth-executed-provider`
-   **Type**: `String (Enum)`
-   **Description**: Informs the client which downstream provider was selected by the L7 gateway's dynamic load balancer:
    -   `openai` | `anthropic` | `gemini` | `groq`
-   **Example**: `x-kryneth-executed-provider: anthropic`

### `x-kryneth-hot-swapped`
-   **Type**: `Integer (Boolean: 0 | 1)`
-   **Description**: Signifies whether the request experienced an automatic failover event due to primary provider failure:
    -   `1`: The primary target failed, and the gateway hot-swapped to an active backup target.
    -   `0`: The primary target answered successfully.
-   **Example**: `x-kryneth-hot-swapped: 1`

### `X-Kryneth-Schema-Stripped`
-   **Type**: `Boolean (true | false)`
-   **Description**: Set to `true` if the gateway's validation middleware stripped unsupported JSON properties or legacy payload schemas from request structures before forwarding to the upstream LLM.
-   **Example**: `X-Kryneth-Schema-Stripped: true`
